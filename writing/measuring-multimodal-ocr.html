Measuring a multimodal OCR pipeline: F1 at IoU, CER, and cost per page

Thomas O'Beirne, October 7, 2026

ManhwaOCR is my pipeline for translating Korean webcomics. It sends each page image to a multimodal model, and the model answers with a JSON list: every piece of text on the page, its type (dialogue, narration, sound effect, sign, or credit), an English translation, and a bounding box. Cleaning and typesetting downstream depend on that box being in the right place.

One response can fail in several ways. This tutorial measures each one separately, using the benchmark harness from the ManhwaOCR repository:

  • Localization: did the model put a box where the text is? Measure precision, recall, and F1 at an intersection over union (IoU) threshold.
  • Reading: did it read the text correctly? Measure character error rate (CER) and word error rate (WER).
  • Translation: how close is the English to a reference? Measure BLEU.
  • Cost: what did each page cost? Count tokens per call.

I used it to compare seven Gemini models with Qwen2.5-VL 7B and 72B, all called through OpenRouter's OpenAI-compatible API.

Before you begin

You need the following:

  • Python 3.11 with jiwer for WER and CER, and sacrebleu for BLEU.
  • Ground truth with boxes. I used Manga109, an academic manga dataset that you can request through a research-use form. Its annotations mark speech-bubble text with xmin, ymin, xmax, and ymax attributes.
  • An OpenRouter API key if you call hosted models.

Step 1: Put every box on the same scale

Before you score anything, convert every predicted box into pixels on the original page. A wrong scale puts every box in the wrong place, and the score drops to zero without an error. The prompt asks for coordinates between 0 and 1. In practice:

  • Gemini models answered on a 0 to 1000 integer grid, whatever the prompt said.
  • Qwen models answered in pixels of the image they received. The pipeline sends pages resized to at most 1,600 pixels on the longer side, so those pixels belong to the resized image.

The repository's parser also handles missing widths and truncated JSON. This shorter version keeps the scaling logic:

import re
from dataclasses import dataclass


@dataclass
class Box:
    x: int
    y: int
    w: int
    h: int


def to_pixels(b, img_w, img_h, model_w, model_h, gemini=False):
    """Map a model bbox dict {x, y, w, h} onto the original page in pixels."""
    x, y, w, h = (float(b.get(k, 0)) for k in ("x", "y", "w", "h"))
    if gemini:  # Gemini answers on a 0-1000 grid, whatever the prompt says
        x, y, w, h = x / 1000, y / 1000, w / 1000, h / 1000
    elif max(x, y, w, h) > 1.0:  # pixels in the resized image the model saw
        x, y, w, h = x / model_w, y / model_h, w / model_w, h / model_h
    return Box(int(x * img_w), int(y * img_h), int(w * img_w), int(h * img_h))

Step 2: Match predictions to ground truth with IoU

IoU divides the overlap of two boxes by the area of their union. A prediction counts as a true positive when its best match among the unmatched ground-truth boxes reaches the threshold. Each ground-truth box can match only once:

def iou(a, b):
    inter_x = max(0, min(a.x + a.w, b.x + b.w) - max(a.x, b.x))
    inter_y = max(0, min(a.y + a.h, b.y + b.h) - max(a.y, b.y))
    inter = inter_x * inter_y
    union = a.w * a.h + b.w * b.h - inter
    return inter / union if union else 0.0


def score_page(gt_boxes, pred_boxes, iou_thresh=0.5):
    matched, tp = set(), 0
    for pred in pred_boxes:
        best_iou, best_idx = 0.0, -1
        for i, gt in enumerate(gt_boxes):
            if i in matched:
                continue
            score = iou(gt, pred)
            if score > best_iou:
                best_iou, best_idx = score, i
        if best_iou >= iou_thresh and best_idx >= 0:
            tp += 1
            matched.add(best_idx)
    return tp, len(pred_boxes) - tp, len(gt_boxes) - tp

The function returns true positives, false positives, and false negatives. Score every page twice: at an IoU of 0.5, the default, and at 0.25. The looser threshold suits irregular speech-bubble shapes.

Step 3: Score only what the ground truth annotates

Manga109 annotates speech-bubble text only, so a correctly found sound effect would count as a false positive. Two filters fix that:

  • Filter predictions by type. Score only entries typed DIALOGUE or NARRATION.
  • Skip pages with no annotations. Covers and title pages have zero ground-truth boxes, so every prediction on them would count against the model.

Sum the counts across pages before you compute rates:

def prf(tp, fp, fn):
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    return p, r, (2 * p * r / (p + r) if p + r else 0.0)

# total_tp, total_fp, total_fn are sums over all scored pages
precision, recall, f1 = prf(total_tp, total_fp, total_fn)

Summing first keeps a page with two bubbles from counting as much as a page with twenty.

Step 4: Read the results with their caveats

My comparison run on May 22, 2026, covered 3 books and 5 pages per book. Five pages had no annotations and were skipped, which left 10 scored pages and 132 ground-truth boxes per model:

gemini-3.5-flash 0.661 0.576 0.615 0.874
gemini-3-flash-preview 0.118 0.144 0.130 0.198
gemini-3.1-flash-lite 0.009 0.008 0.008 0.073
qwen2.5-vl-72b 0.000 0.000 0.000 0.080
qwen2.5-vl-7b 0.000 0.000 0.000 0.000

The other four Gemini models scored an F1 between 0.000 and 0.009 at 0.5. Qwen2.5-VL 7B returned no boxes at all. The 72B model returned 93 boxes, and none of them reached an IoU of 0.5 with a ground-truth box.

Two caveats apply:

  • The benchmark measured my parser as much as the models. The run predates May 28, 2026, when I changed the parser to always read Gemini boxes on the 0 to 1000 grid. I haven't rerun the comparison since, so the near-zero Gemini scores mix model error with my scaling error.
  • Manga109 is Japanese manga, not Korean webcomics. Reading order and layout differ, so the numbers don't transfer directly.

The run still settled one thing: gemini-3.5-flash was the only model with boxes good enough for typesetting.

Step 5: Measure reading accuracy with CER and WER

CER and WER compare extracted text with a reference transcript. Normalize both sides first, so that capitalization and punctuation don't count as errors:

from jiwer import cer, wer


def normalize(text):
    text = re.sub(r"[^\w\s]", " ", text.lower())
    return re.sub(r"\s+", " ", text).strip()

refs = [normalize(t) for t in reference_texts]
hyps = [normalize(t) for t in extracted_texts]
print(f"CER {cer(refs, hyps):.0%}  WER {wer(refs, hyps):.0%}")

Skip pages whose reference has fewer than five words. On a sound-effect-only page, one wrong word in a two-word reference is already a 50% WER, and extra predicted dialogue can push it far past 100%.

Know where your reference came from. Mine was the output of an older OCR pipeline built on PaddleOCR and EasyOCR, not a human transcript, so the test drops pages that look garbled and uses generous limits: 60% WER and 40% CER. Those limits catch catastrophic failures. They don't certify accuracy.

Step 6: Report BLEU, but don't gate on it

For translation, compare the model's English with an existing English release using sacrebleu:

from sacrebleu.metrics import BLEU

bleu = BLEU(effective_order=True)
print(bleu.corpus_score(hypotheses, [references]).score)

Treat BLEU as a relative number across pipeline versions, not as a quality grade. On two full chapters it stayed below 2. Alignment is part of the reason: one English release stitched about six Korean pages into each page, so the reporter groups the longer side into chunks before pairing. My BLEU test never fails on the score.

Step 7: Count tokens and keep one price table

Each response carries a usage object with prompt and completion token counts. Add them up per model, and multiply by a per-million-token price:

import base64
import os
from openai import OpenAI

with open("page_001.jpg", "rb") as f:
    b64 = base64.b64encode(f.read()).decode()
messages = [{"role": "user", "content": [
    {"type": "text", "text": "List every text region on this page as JSON."},
    {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
]}]
client = OpenAI(base_url="https://openrouter.ai/api/v1",
                api_key=os.environ["OPENROUTER_API_KEY"])
response = client.chat.completions.create(
    model="google/gemini-3.1-flash-lite", messages=messages, max_tokens=16384)
usage = response.usage
price = {"input": 0.10, "output": 0.40}  # USD per 1M tokens, from your one table
cost = (usage.prompt_tokens * price["input"]
        + usage.completion_tokens * price["output"]) / 1_000_000

Keeping the prices right was harder than the arithmetic. My repository ended up with three price tables that disagreed:

  • The benchmark and cost-tracker tables listed gemini-3.5-flash at $0.075 input and $0.30 output per million tokens.
  • The OpenRouter table in config.py, updated on May 26, 2026, listed it at $1.50 and $9.00, with a comment that it was the real cost driver.
  • For gemini-3.1-flash-lite, the cost tracker said $0.020 and $0.08, and config.py said $0.10 and $0.40.

The chapter cost reports came from the cost-tracker table, so they used the lower prices. Keep one table, import it everywhere, and check it against your provider's billing.

Set max_tokens with reasoning models in mind. Some Gemini models spend about 3,000 to 4,000 tokens on reasoning, and those count against max_tokens. At 4,096, responses stopped mid-JSON, and a truncated array parses to zero entries, which looks like a model that found no text.

Step 8: Count failures as failures

The first design called Gemini directly and, on a 429 response, retried the page through OpenRouter. In the current code, every call goes through OpenRouter, and a 429 triggers up to four attempts, with waits of 10, 20, 40, and 80 seconds. If all four fail, extract_page() returns a page whose raw response starts with ERROR: instead of raising an exception.

My benchmark loop counts an error only when an exception is raised, so a rate-limited page scored as a page without dialogue. Split failures out explicitly:

from manhwa_ocr.cbz_reader import read_source
from manhwa_ocr.gemini_extractor import GeminiExtractor

extractor = GeminiExtractor("gemini-3.1-flash-lite")
ok_pages, failed_pages = [], []
for page_num, filename, img in read_source("chapter_01.cbz"):
    page = extractor.extract_page(img, page_num, filename)
    if page.raw_gemini_response.startswith("ERROR:"):
        failed_pages.append(page_num)
    else:
        ok_pages.append(page)

Summary

Convert boxes to page pixels before scoring, score only what the ground truth annotates, know where your text reference came from, keep one price table, and count failed calls separately from empty pages.

The ranking settled one decision for me: gemini-3.1-flash-lite stays the default model for extraction, and gemini-3.5-flash, at 15 times the input price and 22.5 times the output price in config.py, is the one to use when the boxes matter.
