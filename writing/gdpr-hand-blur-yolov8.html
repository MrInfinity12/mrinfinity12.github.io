Hide hands before you store the image: a GDPR blur step with YOLOv8

Thomas O'Beirne, October 7, 2026

A camera mounted above a pizza prep counter photographs more than pizza. Staff hands enter the frame, and they carry rings, tattoos, and skin that can identify a person. A quality-control system that stores thousands of these photos has to deal with that under the General Data Protection Regulation (GDPR), and it has to do it before the photos are kept.

PizzaQuality AI, the pizza-grading system I built for a pizza franchise group, handles this with a second YOLOv8 model whose only job is to find hands. This tutorial walks you through the same step: train a hand model, decide per image, blur, and log. The code is adapted from grade_pizza.py in the PizzaQuality AI repository on GitHub. The repository ships demo data and no trained weights, so you bring your own.

The three outcomes

Every image ends in one of three states:

Outcome Condition Action
ok No hand detected Store and grade the image.
blur A hand is detected, but not over the pizza Blur the hand regions, then grade.
reject A hand covers the pizza, or no pizza is found Don't grade the image. Keep it for manual review.

A hand on the tray doesn't change the grade. A hand over the toppings hides what the grading model needs to see.

Before you begin

You need the following:

  • Python 3.11 with ultralytics, opencv-python, and numpy installed.
  • A segmentation model for your product. The code expects a class named pizza_whole. Rename it to match your own class.
  • A few hundred overhead images from your camera in which hands appear.

Step 1: Train a single-class hand model

Label hands as polygons in an annotation tool such as CVAT, with one class named hand. My training set started from 200 captured images, each with at least one labeled hand. The repository's training/augment_dataset.py writes 12 Albumentations variants per image (brightness and contrast, hue and saturation, blur, noise, horizontal flips, rotation up to 15 degrees, scaling, cropping, and CLAHE), which turned 200 images into 2,600.

Train a nano segmentation model from the pretrained checkpoint:

yolo segment train model=yolov8n-seg.pt data=hand_training_aug/dataset.yaml \
    epochs=50 imgsz=640 batch=16

These are the training arguments stored in my hand_best.pt checkpoint. The privacy code uses only the boxes, so a detection model works too.

My own run taught me two things to do differently:

  • Split by source image before you augment. My script shuffled all 2,600 files after augmentation and held out 20% for validation. As a result, 188 of the 200 source images had copies in both the training and the validation set. The checkpoint reports a box precision of 0.95 and a recall of 0.56, and because of that leak, even those numbers are optimistic.
  • Include images without hands. All 200 source images contained a hand, so the model never saw an empty counter or a bare tray as a negative example.

The next step compensates for the low recall.

Step 2: Detect hands at a low threshold

The two possible errors don't cost the same. A missed hand stores personal data. A false detection blurs a few hundred pixels of tray. Set the confidence threshold low to trade precision for recall. Production runs the hand model at 0.1. The threshold started at 0.65, the value my verification script still uses.

Create a file named privacy.py and add the setup and the hand detector:

import csv
import datetime
from pathlib import Path

import cv2
import numpy as np
from ultralytics import YOLO

HAND_CONF = 0.1      # low on purpose: a missed hand is the expensive error
PAD_PX = 20          # extra pixels around each hand box
RIM_FRAC = 0.03      # dilate the pizza mask by 3% of the longer image side

pizza_model = YOLO("best.pt")       # instance segmentation, has a pizza_whole class
hand_model = YOLO("hand_best.pt")   # single class: hand


def detect_hands(img_path):
    result = hand_model(img_path, conf=HAND_CONF, verbose=False, device="cpu")[0].cpu()
    if result.boxes is None:
        return [], 0.0
    boxes = [b.xyxy[0].numpy() for b in result.boxes]
    confs = [float(b.conf[0]) for b in result.boxes]
    return boxes, max(confs, default=0.0)

Both models run with device="cpu", the same as on the production server, where inference runs on the CPU.

Step 3: Build a pizza mask with a safety margin

The decision depends on where the pizza is. Run the product model, take the pizza_whole polygon from masks.xy, and fill it. The polygon is already in original-image pixels, so you don't need to undo the model's letterboxing. The segmentation tends to stop short of the crust, so dilate the mask by 3% of the longer image side, with a floor of 8 pixels:

def pizza_mask(img_path, h, w):
    result = pizza_model(img_path, conf=0.5, verbose=False, device="cpu")[0].cpu()
    if result.masks is None:
        return None
    for i, box in enumerate(result.boxes):
        if result.names[int(box.cls[0])].lower() == "pizza_whole":
            polygon = result.masks.xy[i]
            if len(polygon) < 3:
                return None
            mask = np.zeros((h, w), dtype=np.uint8)
            cv2.fillPoly(mask, [polygon.astype(np.int32)], 1)
            margin = max(8, int(round(RIM_FRAC * max(h, w))))
            kernel = cv2.getStructuringElement(
                cv2.MORPH_ELLIPSE, (2 * margin + 1, 2 * margin + 1))
            return cv2.dilate(mask, kernel)
    return None

The confidence of 0.5 matches the per-class threshold the grader uses for pizza_whole. In the production grader, the pizza model has already run by the time the privacy check starts, so the check reuses that result. This standalone version runs the model itself, and only when a hand is present.

Step 4: Decide with an overlap-first rule

A hand blocks grading only if its box touches the dilated pizza mask:

def decide(boxes, mask, h, w):
    if not boxes:
        return "ok"
    if mask is None:
        return "reject"  # hand present, no pizza to grade
    for x1, y1, x2, y2 in boxes:
        region = mask[max(0, int(y1)):min(h, int(y2)), max(0, int(x1)):min(w, int(x2))]
        if region.size and np.any(region > 0):
            return "reject"  # the hand covers the pizza
    return "blur"

The rule didn't start this simple. On April 16, 2026, I added a second condition: reject any image in which one hand box covers 18% or more of the frame. Three days later I removed it in favor of the overlap-first rule above, where a hand outside the pizza is blurred and graded however large it is. The blur already hides a large hand, so size on its own isn't a reason to throw away the grade.

The reject result also covers a hand with no detectable pizza. In that case there's nothing to grade, and you don't want to keep a raw image of a hand.

Step 5: Blur with padding and overwrite the original

Pad each box by 20 pixels on every side, so the blurred region is 40 pixels wider and taller than the detection. The padding catches rings and wrist details that sit on the edge of the box. The blur uses a 99 by 99 Gaussian kernel:

def blur_hands(img, boxes):
    h, w = img.shape[:2]
    for x1, y1, x2, y2 in map(lambda b: map(int, b), boxes):
        x1, y1 = max(0, x1 - PAD_PX), max(0, y1 - PAD_PX)
        x2, y2 = min(w, x2 + PAD_PX), min(h, y2 + PAD_PX)
        if x2 > x1 and y2 > y1:
            img[y1:y2, x1:x2] = cv2.GaussianBlur(img[y1:y2, x1:x2], (99, 99), 0)
    return img

Write the result over the original file. A blurred copy saved next to an unblurred original protects nobody. If the image also lives in object storage, overwrite that copy too, so the raw upload doesn't survive.

Step 6: Log every decision

Write one CSV row per privacy event, and record the hand model's own confidence:

def log_event(log_dir, decision, img_path, store_id, hand_conf):
    log_path = Path(log_dir) / f"privacy_{decision}.csv"
    new_file = not log_path.exists()
    with open(log_path, "a", newline="") as f:
        writer = csv.DictWriter(
            f, fieldnames=["timestamp", "filename", "store_id", "hand_confidence"])
        if new_file:
            writer.writeheader()
        writer.writerow({
            "timestamp": datetime.datetime.now().isoformat(timespec="seconds"),
            "filename": Path(img_path).name,
            "store_id": store_id,
            "hand_confidence": round(hand_conf, 3),
        })


def protect(img_path, store_id, log_dir="."):
    img = cv2.imread(img_path)
    if img is None:
        return "reject"
    h, w = img.shape[:2]
    boxes, hand_conf = detect_hands(img_path)
    decision = decide(boxes, pizza_mask(img_path, h, w) if boxes else None, h, w)
    if boxes:
        cv2.imwrite(img_path, blur_hands(img, boxes))  # overwrite the original
        log_event(log_dir, decision, img_path, store_id, hand_conf)
    return decision


if __name__ == "__main__":
    import sys
    for path in sys.argv[1:]:
        print(path, protect(path, store_id="demo"))

Two choices in this version matter:

  • It blurs rejected images too. The decision controls grading only. Every detected hand gets blurred, so an image held back for manual review doesn't expose anyone either.
  • It logs the hand model's own confidence. Log the number that tells you how sure the hand model was, not the threshold or another model's score. That's the number you want when you audit a borderline case later.

Step 7: Check the decisions by eye

Run the script on a folder of images that weren't in the training set:

python privacy.py test_images/*.jpg

For a visual check, the repository's tools/verify_hand_model.py applies the same decision logic and writes annotated copies: green for ok, yellow for blur, red for reject, the outline of the dilated pizza mask, and a banner with the decision, hand count, and highest confidence. I ran it on a held-out set of 23 images that weren't used for training. The annotated copies show each decision at a glance, which makes wrong calls easy to spot.

Where this design falls short

This step protects the images that the grader and the dashboard keep, but it isn't the strictest possible design:

  • Blur on the device when you can. If the camera device uploads raw images and a server blurs them later, the raw images sit in storage until the blur runs. Running the hand model on the edge device before upload means no unblurred hand leaves the site. A small detection model is light enough for a Raspberry Pi 5.
  • Boxes miss forearms. A box drawn around a hand can cut through a wrist or a tattoo on the forearm. Expanding the model to forearms is on the project roadmap.
  • Recall is the weak point. A low threshold compensates for a model that misses hands, but it doesn't fix it. More varied training data, including negatives and a clean validation split, is the real fix.

Summary

Train a single-class hand model on data split by source image, run it at a low threshold, reject only when a hand covers the product, blur every detected hand with padding over the original file, and log each decision with the hand model's own confidence.
